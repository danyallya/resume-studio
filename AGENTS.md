# Project working rules
- Build Forma as a trusted resume and portfolio studio for real career transitions. Maintain its paper, ink and teal editorial direction.
- Start every day by reading this file, BACKLOG.md and Git status, reviewing prior changes and debugging open issues.
- Every session includes code review, targeted tests, the day's implementation, documentation and backlog updates, debugging and a final regression review. Run tests/typecheck/build when dependencies are available.
- Keep career data private and avoid logging or committing personal details. Clearly mark synthetic starter content.
- Preserve readable print layout, responsive screens, both themes, keyboard support and accessible form labels.
- Use React, TypeScript, Vite, Mantine and React Icons; favor typed form models and reusable sections.
- Update BACKLOG.md after each run, record new work, and prepare the next ticket explicitly.
- Keep .npmrc local and ignored. Never commit credentials, resumes, personal exports, .env or build output; do not rewrite Git history.
- Restrict changes to this repository and use meaningful commits on descriptive day branches after checks pass.
